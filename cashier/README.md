# Касса «Пиксельного костра»

Cloudflare Worker + D1. Продаёт четвертаки, держит леджер, принимает
монетку в щель.

Зал (`hall/`) живёт на GitHub Pages — это статика, сервер там невозможен,
поэтому касса стоит отдельно, а зал ходит к ней по HTTP.

## Что уже работает

- пачки четвертаков с ценами **на сервере** (клиент присылает только id);
- подтверждение оплаты **серверным capture**, не редиректом браузера;
- идемпотентность: повторный capture одного заказа не начисляет дважды;
- кошелёк = подписанный HMAC токен + серийник в леджере против реплея;
- монетка в щель списывается атомарно — две вкладки не потратят одну;
- аудит: кто во что играл (`spends`).

Провайдер выбирается сам: есть ключи PayPal — работает PayPal, нет —
mock, и зал честно пишет игроку «демо-оплата».

## Запуск локально

```bash
npm install
npm run db:init:local      # схема в локальную D1
npm run dev                # http://127.0.0.1:8788
```

Проверить: `curl http://127.0.0.1:8788/api/health`

Чтобы зал ходил в локальную кассу, в `hall/config.js`:

```js
window.PKF_CASHIER_URL = 'http://127.0.0.1:8788';
```

## Деплой

```bash
wrangler d1 create pkf-cashier          # database_id -> wrangler.toml (оба места)
npm run db:init:remote
wrangler secret put WALLET_SECRET       # длинная случайная строка
wrangler deploy
```

Затем прописать боевой адрес в `hall/config.js` и запушить — Pages
подхватит.

**WALLET_SECRET менять нельзя** после запуска: все выданные токены
подписаны им, смена обнулит кошельки живых игроков.

## Включить настоящий PayPal

```bash
wrangler secret put PAYPAL_CLIENT_ID
wrangler secret put PAYPAL_SECRET
# PAYPAL_ENV: sandbox (по умолчанию) | live
```

Появились ключи — провайдер переключается сам, код не трогаем. Остаётся
одно: подключить в зале окно PayPal JS SDK, которое вызовет
`/api/capture` в `onApprove`. Сейчас на этом месте честный отказ
(`needsCheckout`), а не тихая выдача монет.

## Эндпоинты

| Метод | Путь           | Что делает                                  |
|-------|----------------|---------------------------------------------|
| GET   | `/api/health`  | жив ли, какой провайдер, демо или деньги    |
| GET   | `/api/packs`   | витрина пачек с ценами сервера              |
| GET   | `/api/wallet`  | баланс по токену                            |
| POST  | `/api/order`   | завести заказ (и кошелёк, если его не было) |
| POST  | `/api/capture` | подтвердить оплату, начислить монеты        |
| POST  | `/api/spend`   | монетка в щель: списать один четвертак      |

Токен ходит в `Authorization: Bearer <token>` и обновляется почти в
каждом ответе — клиент обязан сохранять свежий.

## Честные пределы (знаем и принимаем)

- **Кошелёк не привязан к человеку.** Очистил хранилище браузера —
  монеты потеряны. Для аркадного зала это приемлемо: так же теряется
  забытый в автомате четвертак. Учётки/восстановление — отдельный шаг.
- **Заказы можно спамить** — создание заказа пишет строку в `payments`
  без оплаты. Мусор ограничен, но на будущее нужен rate limit по IP.
- **Сбой между «пометить заказ» и «начислить монеты»** оставит игрока
  без монет по оплаченному заказу. Выбрано сознательно: обратный
  порядок при том же сбое выдавал бы монеты дважды. Лечится по
  квитанции руками.
- **Запуск игры не проверяется криптографически**: зал открывает игру
  после успешного списания, но сама игра — статика и токен не спросит.
  Обход даёт бесплатную игру, не деньги.
