# Деньги: PayPal → четвертаки

Ответ на главный вопрос Юджина: **как подтвердить, что денежка заплачена**.

## Официальный путь — PayPal Orders API v2 (server-side confirm)

Подтверждение оплаты — это НЕ редирект пользователя обратно на сайт
(редирект подделывается адресной строкой). Подтверждение — это ответ
PayPal-сервера на **наш** серверный запрос capture. Поток:

```
Браузер                Наш Go-сервер                 PayPal
   │  «купить 8 монет»      │                           │
   │───────────────────────>│  POST /v2/checkout/orders │
   │                        │──────────────────────────>│  (intent=CAPTURE,
   │   order_id             │<──────────────────────────│   amount=1.00 USD)
   │<───────────────────────│                           │
   │  PayPal JS SDK открывает окно оплаты (order_id)    │
   │  пользователь платит внутри окна PayPal            │
   │  onApprove(order_id)   │                           │
   │───────────────────────>│  POST /v2/checkout/orders/{id}/capture
   │                        │──────────────────────────>│
   │                        │   status: "COMPLETED"     │  ← ВОТ ПОДТВЕРЖДЕНИЕ
   │                        │<──────────────────────────│
   │  Set-Cookie: wallet=…  │  (зачисляем монеты)       │
   │<───────────────────────│                           │
```

- **Auth:** сервер получает OAuth2-токен по client_id+secret
  (`POST /v1/oauth2/token`, Basic auth). Ключи — только на сервере,
  в env, в гит не попадают.
- **Sandbox:** `api-m.sandbox.paypal.com` + sandbox-аккаунты покупателя
  и продавца из developer.paypal.com. Прод: `api-m.paypal.com`.
- **Идемпотентность:** запоминаем capture_id обработанных платежей
  (SQLite), повторный capture того же order_id монет не добавляет.

## Страховка — webhook (опционально, этап 2)

`PAYMENT.CAPTURE.COMPLETED` на наш `/paypal/webhook` с проверкой
подписи (`/v1/notifications/verify-webhook-signature`). Ловит случаи
«заплатил, но закрыл вкладку до onApprove». В v1 можно жить без него:
capture-путь покрывает 99%, а спорные — по квитанции на почту.

## Кошелёк — токены в куке (решение Юджина: без выпендрежа)

Кука `wallet` = `{coins, serial}` + HMAC-SHA256 подпись серверным
секретом (тот же приём, что PXCF-ключи десктопа). Сервер при трате
проверяет подпись, уменьшает coins, переподписывает. Реплей старой куки
с большим балансом отсекается серийником в SQLite-леджере (serial
инкрементится при каждой операции; кука со старым serial = невалидна).

Ломается? Конечно — клиент есть клиент. Но: подпись не подделать без
секрета, реплей ловится леджером, а больше нам и не надо — мы не жадные.
Самое ценное (лекции) вообще бесплатно.

## Цены (на обсуждение)

| Вариант      | Пачка         | Цена запуска | Комментарий            |
|--------------|---------------|--------------|------------------------|
| Quarter-канон| $1 = 4 монеты | 25¢          | аутентично, дорого     |
| Quarter-щедрый| $1 = 8 монет | 12.5¢        | моя рекомендация       |
| Nickel       | $1 = 20 монет | 5¢           | «бесплатно с ритуалом» |

PayPal-комиссия на микроплатежах злая (fixed fee ~$0.49 на транзакцию
обычного тарифа) — поэтому продаём ПАЧКИ от $1, не по монетке. Есть
спец-тариф micropayments (5% + $0.09), включается в аккаунте — глянуть
при настройке прода.
